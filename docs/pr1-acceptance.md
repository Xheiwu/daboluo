## 已确认并修复

| 严重度 | 缺陷与触发方式 | 修复 |
|---|---|---|
| P1 | `handleOfflineReturn` 先将 running=false，但延迟 800ms 才发奖。在该窗口保存/关闭会留下未发奖、已停止的状态。 | 奖励与标记同步更新并保存，延迟任务只显示结果；显示不再发第二次奖。 |
| P2 | 后台超过 600 秒时，`applySettlement` 更新 player.idle.pity，随后 `persist` 用旧 run.pity 覆盖它。 | 补算同时更新运行态保底。 |
| P2 | SaveSystem 保存玩家奖励时，不同步塔运行层数和 lastActive；进度最多落后一次 persist 周期，重开可重复计算这段时间。 | 保存与关闭前同步塔快照，进入塔立即保存。以最后处理时间作检查点，隐藏后未处理的时间不会被保存操作抹掉。 |
| P2 | 镇妖塔覆盖层仅拦截鼠标/部分触控冒泡，window keydown 仍处理 F、1/2/3、Enter；原 ARPG update/draw 也继续执行。 | 塔与闭关面板独占模拟和快捷键，自动存档保留；退出后恢复原 ARPG。清理入塔前残留的鼠标和移动目标。 |
| P2 | 部分旧 idle.totals 缺少 seconds/offlineClaims 等字段时，后续 += 会产生 NaN。 | 补齐累计字段并保留已有有效值。 |
| 防御性修复 | IdleMode 没有读档生命周期，无法在同一上下文显式重置旧运行态、面板或延迟回调；旧存档缺少 idle 时依赖残留全局状态。标准刷新切槽本身会重建上下文，不能据此断言正常切槽已经串档。 | startGame 加入显式 onSaveLoaded；清理运行态，缺字段使用独立默认状态，以载入代次拒绝旧延迟任务。真实浏览器切槽仍待实测。 |

另外，后台恢复时长纳入 totals.seconds。没有修改掉率、难度、离线效率/上限、技能或养成规则。
